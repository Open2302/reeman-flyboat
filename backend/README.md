# Backend пульта

Python 3.10 или новее, без сторонних библиотек. HTTP-сервер раздаёт пульт,
SQLite хранит общий черновик, маршрут, текущую точку маршрута, состояние возврата,
последние показания робота и последнюю принятую команду лифта.

## Запуск

Из корня проекта:

```powershell
python backend/server.py --demo
```

Открыть **http://127.0.0.1:8000/**. Деморежим использует симулятор и отдельную
базу `backend/data/demo.sqlite3`; запросов к настоящему роботу нет.

Подключение настоящего робота:

```powershell
python backend/server.py --robot-url http://10.6.20.95
```

База по умолчанию — `backend/data/robot.sqlite3`. Если команда `python`
не найдена, установите Python 3.10+ и повторно откройте терминал.
Если в Windows используется launcher, вместо `python` можно написать `py`.

Для нескольких пультов в доверенной локальной сети:

```powershell
python backend/server.py --host 0.0.0.0 --port 8000 --robot-url http://10.6.20.95
```

На остальных устройствах открыть `http://IP-КОМПЬЮТЕРА-С-СЕРВЕРОМ:8000/`.
Сервер должен постоянно работать на компьютере с доступом к роботу.
Открывать HTML через `file://` больше не нужно: страница перенаправит на
`http://127.0.0.1:8000/`.

## Что сохраняется и как восстанавливается

- Перезагрузка и закрытие браузера не влияют на выполнение: точки отправляет
  единственный фоновый поток backend, а страницы только читают состояние.
- Обычный вызов отдельной точки хранится в `navigation` и не меняет состояние
  маршрута или нижнюю строку. Кнопки точек остаются доступны при обычном вызове.
  Вне зарядки смена направления требует подтверждения «Вы хотите прервать
  направление?». Подтверждение связано с текущей целью и вызовом: если другой
  пульт успел изменить направление, нужно подтвердить новое состояние.
- Во время маршрута обычные вызовы и редактирование списка блокируются как
  на странице, так и в API. Ручное управление лифтом тоже заблокировано в обоих
  направлениях. Доступ к отмене и закрытие окна остаются доступны.
  Признак `route.locked` снимается только при подтверждённом завершении или
  явной отмене. Ошибка команды не освобождает управление и не запускает
  автовозврат. Если GET с аварийной кнопкой пришёл после ошибки POST, сохраняется
  тот же маршрут и восстанавливается его текущий шаг после отпускания кнопки.
- Общий список точек сохраняется после каждого добавления, удаления, очистки
  или перестановки. Проверка версии защищает от потери правок в другом окне.
- Запуск фиксирует отдельную копию маршрута. Перед первым движением сервер
  отправляет подъём лифта и ждёт подтверждения команды. При ошибке движение не
  начинается. В конце добавляется зарядка, на ней лифт остаётся поднятым.
- После перезапуска backend загружает текущий шаг и продолжает ожидание
  прибытия по свежим данным. Перед отправкой следующей точки фиксирует намерение
  в SQLite. Если сервер завершился во время отправки, он сверяет цель робота.
  При неоднозначном результате останавливает маршрут с сообщением, вместо
  повторной отправки потенциально уже принятой команды.
- Отмена сразу исключает все оставшиеся точки и сохраняет возврат на зарядку.
  Команду зарядки отправляет тот же поток после завершения предыдущего запроса.
  Возврат переживает перезапуск backend; после прибытия статус — «отменён».
  Кнопки разблокируются сразу после отмены, без ожидания зарядки. Можно менять
  список, запускать новый маршрут или подтверждать обычный вызов в другую точку.
  Подтверждённый вызов прекращает прежний возврат: отложенная команда зарядки
  не сможет перезаписать новое направление. Подтверждение выводится в собственном
  модальном окне пульта с двумя вариантами: оставить прежнее направление или изменить.
- При потере связи или нажатой аварийной кнопке переход к следующей точке
  приостанавливается. Старые показания помечаются как неактуальные.
- Прибытие: совпадает цель, дистанция ≤ 1 м, линейная и угловая скорости около
  нуля; нужны три подтверждения с интервалом 2 секунды. На рабочей точке сервер
  опускает лифт. После принятия этой команды сохраняется двухминутный таймер.
  После 120 секунд одновременно отправляются подъём лифта и следующая точка.
  На конечной зарядке маршрут завершается без двухминутной остановки, только
  после подтверждения зарядки `chargeFlag == 2`. Нулевой дистанции и остановки
  недостаточно: робот мог остановиться из-за аварийной кнопки.
  Ошибка команды лифта останавливает маршрут. Неоднозначный результат команды
  лифта после перезапуска требует проверки оператором.
- Двухминутный таймер сохраняется в SQLite и переживает перезапуск.
  Отсчёт не останавливается при нажатии аварийной кнопки или потере связи.
  Отправка следующей точки разрешена только после отпускания кнопки и появления
  свежих данных. Если ожидание уже истекло, дополнительная пауза не добавляется.
  Аварийная кнопка не удаляет маршрут, не меняет текущий шаг и не вызывает
  возврат на зарядку. Если робот сбросил цель во время движения, после отпускания
  кнопки сервер восстановит текущую цель, сохранив оставшийся маршрут. Сброс цели
  во время ожидания не сбрасывает установленный срок ожидания.
- Вне активного маршрута непрерывная стоянка на одной точке 10 минут запускает
  возврат на зарядку. Обычный вызов и автовозврат не меняют нижний статус маршрута.
  Движение, смена цели, потеря связи или перерыв наблюдения более 5 секунд
  сбрасывают этот таймер. На зарядке таймер не запускается.
  Сообщение «Автовозврат на зарядку» показывается не более 6 секунд и исчезает
  раньше при прибытии, смене цели или запуске маршрута.
- Статус-бар обновляется отдельными параллельными GET к API робота каждые 500 мс,
  независимо от загрузки общего состояния. В деморежиме используются GET
  `/api/telemetry/base`, `/api/telemetry/speed`, `/api/telemetry/nav`. Если браузер
  блокирует прямой GET из-за CORS, автоматически используются эти же GET backend.
  При дистанции ≥ 1 м показывается движение, ближе — по `vx`; переключение после
  трёх одинаковых показаний.
- Backend опрашивает датчики параллельно в отдельном потоке. Команды получают
  сигнал сразу после записи в SQLite и не ждут завершения опроса. POST роботу
  завершается после HTTP-подтверждения, без ожидания неиспользуемого тела ответа.

## Настройка времени ожидания

В начале [main.js](../code/TestHtml/main.js) заданы значения **в секундах**:

```javascript
const ROUTE_WAIT_SECONDS = 120;   // Остановка на рабочей точке.
const IDLE_RETURN_SECONDS = 600;  // Стоянка перед автоматическим возвратом.
```

Указывайте положительные числа. После сохранения файла работающий backend
автоматически подхватит изменения при очередном опросе. Новая длительность
остановки применяется к следующим остановкам; уже начатая сохраняет прежний
остаток. Порог автовозврата применяется при следующей проверке стоянки.
При некорректном изменении сервер продолжает использовать последние корректные
значения и записывает ошибку в журнал. В пульте подсказка и отсчёт используют
значения, фактически принятые сервером.

SQLite не заменяет датчики. Положение лифта в имеющемся описании API отсутствует:
подпись кнопки опирается на последнюю принятую команду. При ручном управлении
лифтом вне этого backend она может отличаться от физического положения.
Нативные коды успешного завершения/ошибки навигации `res`/`reason` пока не
документированы, поэтому проверка прибытия использует `goal`, `dist`, `vx`.

## API

| Метод | Путь | Тело |
|---|---|---|
| GET | `/api/state` | Общее состояние, телеметрия и время её обновления |
| GET | `/api/telemetry/{base,speed,nav}` | Один актуальный ответ телеметрии |
| POST | `/api/draft` | `{"version": 0, "points": ["ОП1", "ВП4"]}` |
| POST | `/api/route/start` | `{"version": 1}` |
| POST | `/api/route/cancel` | `{}` |
| POST | `/api/navigate` | `{"point": "ОП1"}`; вне зарядки API возвращает `confirmation_required` и токен, который нужно передать в поле `confirmation` после согласия оператора |
| POST | `/api/lift` | `{"direction": "up"}` или `{"direction": "down"}` |

Все POST требуют `Content-Type: application/json`. Командные запросы из другого
сайта отклоняются. Авторизации пользователей нет: запуск на всех интерфейсах
предназначен только для доверенной локальной сети, без публикации в интернете.
База и исходники backend не раздаются HTTP-сервером. Второй экземпляр сервера
с той же базой блокируется файловой блокировкой.

## Проверки

```powershell
python backend/test_server.py
```

Тесты используют временные базы и подставного робота. Проверяются восстановление
после перезапуска, конфликт правок, последовательность команд, отмена во время
отправки, потеря связи, аварийная кнопка, движение, лифт и HTTP API.

Для проверки вручную в деморежиме: собрать и запустить маршрут, обновить страницу,
открыть второй пульт, затем отменить маршрут. Для проверки перезапуска остановить
сервер через Ctrl+C и снова запустить с тем же `--demo` и той же базой.
Для отдельной базы можно передать `--db ПУТЬ`. Базу нельзя одновременно
использовать для деморежима и настоящего робота.

Запуск при загрузке Windows можно настроить через Планировщик заданий: программа —
полный путь к `python.exe`, аргументы — полный путь к `backend/server.py` и нужные
параметры. Пути к статическим файлам и базе по умолчанию не зависят от рабочей папки.
